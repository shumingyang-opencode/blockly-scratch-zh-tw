1.1 為什麼從積木開始

視覺化程式設計讓你把「積木」拖到畫布上拼起來，就完成一支程式。它把程式設計的兩大難關——語法與邏輯——分開處理：先專注邏輯，語法之後再說。

面向文字程式積木程式
語法要背（分號、括號、縮排）免（接頭卡合就對了）
即時回饋編譯/執行後才知道拖上去就能看結果
除錯看錯誤訊息直覺看積木哪拼錯
入門年齡較高小學即可
核心觀念：積木程式不是「簡化版的程式」，而是同一套邏輯的另一種表達——學會積木，等於學會「演算法思維」，之後轉文字只是「翻譯」。

1.2 教育價值

  • 計算思維：拆解問題、找規律、設計演算法。
  • 創造力：作品看得見、可分享、有成就感。
  • 失敗安全：拼錯就拆掉重拼，允許犯錯。
  • 跨領域：遊戲=邏輯+數學，動畫=藝術+程式。

1.3 Scratch vs Blockly：兩種定位

面向Scratch（MIT）Blockly（Google）
本質完整的學習產品開源程式庫（引擎）
目標讓學習者做出作品讓開發者做出工具
對象學生/教師/創作者程式設計師
代表作scratch.mit.eduMakeCode、App Inventor
社群大量分享專案開發者文件/論壇
一句話：Scratch 是「商店裡已做好的玩具」，Blockly 是「做玩具的引擎」。兩者都教你積木邏輯，但舞台不同。

1.4 Worked Example：同一個概念，兩種工具

範例
概念：「按按鈕就 +1」

Scratch：
  當 ⚑ 被點擊
  重複無限次
    如果 <按下 [空白鍵] 呢？>
      將 [分數] 增加 1
    如果 <分數 = 10>
      說出 "你贏了！"

MakeCode（Blockly 家族）：
  on button A pressed
    change score by 1
  on start
    forever
      if score = 10 then
        show string "你贏了！"

動手：用一句話說出「Scratch」與「Blockly」最大的不同，並查一個兩者的共同積木。

1.5 常見迷思

  • 「積木程式不是真程式」——錯。MakeCode 的積木背後就是 JavaScript。
  • 「只適合小孩」——錯。Blockly 是專業工具（MakeCode）的核心。
  • 「學了積木要全部重學」——不必。邏輯相通，只差語法。
